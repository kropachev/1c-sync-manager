## Общее описание

Справочник "Запросы к внешним источникам (МС)" (`МС_ЗапросыКВнешнимИсточникам`) описывает один шаг обмена: откуда получить данные или куда их отправить, с какими параметрами и какими процедурами их подготовить и обработать. Запросы собираются в цепочку в настройке синхронизации, а соединение с источником берется из ее поля "Соединение".

Устройство:

- **Запрос** - один шаг обмена: загрузка (получить данные из источника) или выгрузка (отправить данные в источник).
- **Способ получения данных** определяет транспорт: файлы из каталога, файлы с FTP, очередь RabbitMQ или код на встроенном языке.
- **Процедуры подготовки и обработки** - прикладная логика на встроенном языке: что делать с полученными данными и что отправлять. Сам запрос только доставляет данные.
- **Значения параметров и настройка соответствий** - настройки прикладной логики, которые меняются без доработки кода.

## Шапка элемента

| Поле | Назначение |
|---|---|
| Код, Наименование | Наименование показывается в журнале обмена и в командах синхронизации на формах объектов |
| Тип обмена | "Загрузка" - получить данные из источника, "Выгрузка" - отправить данные в источник |
| Процедура подготовки данных перед обменом | Процедура, которая выполняется до обращения к источнику, например `МойМодуль.ПодготовитьЗаказы` |
| Процедура обработки данных после обмена | Процедура, которая обрабатывает полученные данные или результат отправки, например `МойМодуль.ЗагрузитьЗаказы` ||

Процедуры указываются полным именем: `ИмяОбщегоМодуля.ИмяПроцедуры`. Обе необязательны: например, отправка в очередь готового текста сообщения обходится без процедур.  

## Способы получения данных

Способ выбирается переключателем на закладке "Получение данных". Для каждого способа показываются свои поля.

### Файлы из каталога

Чтение и запись файлов в каталоге, доступном серверу 1С: локальном или сетевом. Пути указываются так, как их видит сервер 1С, например `\\fileserver\exchange\in`.

**Загрузка** возвращает массив файлов (`Массив` из `Файл`), найденных в каталоге по маске. Сами файлы читает процедура обработки.

| Поле | Назначение |
|---|---|
| Каталог файлов | Каталог, из которого читаются файлы |
| Маска файлов | Например `*.xml` или `orders_*.csv`. Пусто - `*.xml` |
| Копировать файлы в локальный каталог | Перед обработкой скопировать файлы в "Каталог сохранения новых файлов". Процедура обработки получит файлы из этого каталога |
| Модифицировать имя файла | При копировании добавить к имени дату и время, например `orders_15_01_2026_10_20_00.xml`. Если такой файл уже есть, добавляется еще и уникальный идентификатор |
| Каталог сохранения новых файлов | Куда копируются файлы |
| Каталог сохранения обработанных файлов, Каталог сохранения ошибок | Каталоги, в которые процедура обработки может переносить обработанные и ошибочные файлы. Сам запрос файлы туда не переносит |
| Удалять файлы из каталога источника | Удалить файл в источнике после успешного копирования. Включает копирование, даже если флажок копирования снят |

При копировании все три каталога сохранения должны существовать, иначе запрос завершится ошибкой "Каталог ... не существует". Временные файлы Excel (имя начинается с `~$`) при копировании пропускаются.

С копированием процедура обработки получает все файлы каталога сохранения новых файлов по маске, включая оставшиеся от прошлых запусков. Поэтому процедура должна переносить обработанные файлы из этого каталога, например в каталог обработанных файлов.

**Выгрузка** записывает в "Каталог файлов" файлы, которые подготовили процедура подготовки или предыдущие строки запуска. Элемент массива выгрузки - структура с полями `ИмяФайла` и `АдресВременногоХранилища` (двоичные данные файла во временном хранилище). После записи в элемент добавляется поле `ФайлВыгрузилсяУспешно`.

### Файлы с FTP

Чтение и запись файлов в каталоге FTP-сервера. В поле "Соединение" настройки синхронизации должна быть настройка подключения вида FTP.

**Загрузка** возвращает массив файлов. Сами файлы читает процедура обработки.

| Поле | Назначение |
|---|---|
| Каталог файлов | Каталог на FTP-сервере, например `/outgoing` |
| Маска файлов | Например `*.xml`. Пусто - `*.xml`. Применяется только при копировании, к уже скачанным файлам |
| Копировать файлы в локальный каталог | Перед обработкой скачать файлы в "Каталог сохранения новых файлов" на сервере 1С. Процедура обработки получит файлы из этого каталога |
| Каталог сохранения новых файлов | Каталог на сервере 1С, куда скачиваются файлы |
| Каталог сохранения обработанных файлов, Каталог сохранения ошибок | Каталоги на сервере 1С, в которые процедура обработки может переносить обработанные и ошибочные файлы. Сам запрос файлы туда не переносит |
| Удалять файлы из каталога источника | Удалить файл на FTP-сервере после успешного скачивания. Включает копирование, даже если флажок копирования снят |

Что получает процедура обработки:

- без копирования - массив `FTPФайл` со всеми файлами каталога FTP-сервера, маска не применяется;
- с копированием - массив `Файл` из каталога сохранения новых файлов по маске, включая файлы, оставшиеся от прошлых запусков. Поэтому процедура должна переносить обработанные файлы из этого каталога.

При копировании скачиваются все файлы каталога FTP-сервера, независимо от маски. С флажком "Удалять файлы из каталога источника" с сервера удаляются тоже все скачанные файлы, в том числе не подходящие под маску. Если в каталоге FTP лежат файлы, которые обрабатывать не нужно, используйте отдельный каталог.

При копировании все три каталога сохранения должны существовать, иначе запрос завершится ошибкой "Каталог ... не существует".

**Выгрузка** записывает в "Каталог файлов" на FTP-сервере файлы, которые подготовили процедура подготовки или предыдущие строки запуска. Элемент массива выгрузки - структура с полями `ИмяФайла` и `АдресВременногоХранилища` (двоичные данные файла во временном хранилище). После записи в элемент добавляется поле `ФайлВыгрузилсяУспешно`.

### RabbitMQ (HTTP)

Чтение и публикация сообщений очереди RabbitMQ через Management HTTP API. Подходит для небольших потоков сообщений: каждое чтение и каждая публикация - отдельный HTTP-запрос.

Подключение: в настройке синхронизации - настройка подключения вида HTTP, в поле "Сервер" которой указан корень Management API, например `https://rabbitmq.example.com/api` или `http://rabbitmq.example.com:15672/api`. У пользователя RabbitMQ должны быть права на чтение и запись нужных очередей.

| Поле | Назначение |
|---|---|
| Имя очереди | Очередь, из которой читаются сообщения или в которую они публикуются |
| Виртуальный хост | `/` - виртуальный хост по умолчанию. Пусто - виртуальный хост уже входит в базовый путь адреса сервера (так бывает, когда перед RabbitMQ стоит шлюз) |
| Количество сообщений | Сколько сообщений забирать за один запуск. Пусто - 10 |
| Удалять сообщения после прочтения | Включено - прочитанные сообщения удаляются из очереди. Выключено - остаются в очереди и будут прочитаны снова при следующем запуске |
| Точка обмена (exchange) | Через какую точку обмена публиковать. Пусто - `amq.default`: она доставляет сообщение в очередь с именем, указанным в поле "Имя очереди" |
| Текст сообщения | Текст, который публикуется, если процедура подготовки не подготовила сообщений. Удобно для проверки обмена |

**Загрузка** возвращает массив сообщений. Сообщение - структура с полями ответа RabbitMQ: текст сообщения в поле `payload`, а также `routing_key`, `redelivered`, `properties` и другие. Каждое полученное сообщение записывается в журнал обмена (операция `RabbitMQ.Получение`), текст сообщения - в "Данные сообщения". Пустая очередь в журнал не пишется.

Если очередь прочитать не удалось, ошибка записывается в журнал обмена, а процедура обработки все равно вызывается с пустым массивом. Подробности запроса (успех, адрес, код ответа, текст ошибки) лежат в `СтруктураПараметров.РезультатПолученияRabbitMQ`.

**Выгрузка** публикует сообщения из массива выгрузки. Элемент массива - строка (текст сообщения) или структура:

| Поле | Содержимое |
|---|---|
| `ТекстСообщения` | Текст сообщения (payload) |
| `Заголовки` | Необязательное: структура или соответствие заголовков AMQP сообщения |

После публикации в элемент добавляются поля `ОтправленоУспешно`, `РезультатОтправки` и `ЗапросОтправки`: по ним процедура обработки узнает результат по каждому сообщению. Публикуются только еще не отправленные элементы, поэтому сообщение, опубликованное одной строкой выгрузки, следующая строка того же запуска не дублирует.

Сообщения публикуются как постоянные (`delivery_mode` = 2) с типом `application/json`. Отправка успешна, если RabbitMQ подтвердил доставку в очередь. Если очереди с таким именем нет, отправка считается неудачной. Каждая публикация записывается в журнал обмена (операция `RabbitMQ.Отправка`).

Если отправлять нечего, а поле "Текст сообщения" пусто, в журнал пишется запись "Нет сообщений для отправки в очередь ...".

### Произвольный результат

Данные получает код на встроенном языке из поля "Код запроса". Способ для источников без готового транспорта: база данных через ADO, нестандартный HTTP API, внешняя компонента. Требует навыков программирования.

| Поле | Назначение |
|---|---|
| Текст запроса | Текст запроса к источнику, например SQL. Доступен коду в переменной `ТекстЗапроса` |
| Использовать код запроса | Показывает поле "Код запроса" |
| Код запроса | Код на встроенном языке. Должен присвоить результат переменной `РезультатЗапроса` |

Код выполняется всегда, когда выбран этот способ, независимо от флажка "Использовать код запроса". Коду доступны переменные:

| Переменная | Содержимое |
|---|---|
| `СтруктураСоединения` | Соединение из настройки синхронизации, структура с полями: `Соединение` - объект соединения (`HTTPСоединение`, `FTPСоединение` или объект произвольного подключения), `СтрокаОшибок` - ошибка создания соединения, `Заголовки` - заголовки настройки HTTP, `БазовыйПуть` - путь из адреса HTTP-сервера, `ОсновнойКаталогFTP` - основной каталог FTP |
| `СтруктураПараметров` | Параметры обмена, в том числе период синхронизации `НачалоПериода`, `ОкончаниеПериода` и значения параметров |
| `ТекстЗапроса` | Значение поля "Текст запроса" |
| `Выгруза` | `Истина` при выгрузке. Данные для отправки - в `СтруктураПараметров.РезультатВыгрузки` |
| `РезультатЗапроса` | Результат, который получит процедура обработки |

Пример: чтение из SQL Server через подключение вида "Произвольное" с ADO.

Текст запроса:

```
SELECT OrderId, CustomerInn, Amount FROM dbo.Orders WHERE Status = 'new'
```

Код запроса:

```
Набор = СтруктураСоединения.Соединение.Execute(ТекстЗапроса);
РезультатЗапроса = МС_СинхронизацияСервер.ТаблицаЗначенийИзCOMОбъекта(Набор);
```

Пример: чтение JSON из HTTP API через подключение вида HTTP.

```
Ответ = МС_ПодключенияСервер.ВыполнитьHTTPЗапрос(СтруктураСоединения, "GET",
	СтруктураСоединения.БазовыйПуть + "/orders?from=" + Формат(СтруктураПараметров.НачалоПериода, "ДФ=yyyy-MM-dd"));
РезультатЗапроса = МС_ПодключенияСервер.ПрочитатьОтветJSON(Ответ);
```

## Значения параметров

Таблица на закладке "Значения параметров" хранит настройки прикладной логики: каталоги, коды, ссылки на элементы справочников. Процедуры подготовки и обработки читают их по имени, поэтому одну и ту же процедуру можно использовать в нескольких запросах с разными значениями.

| Колонка | Назначение |
|---|---|
| Имя параметра | Имя, по которому процедура читает значение |
| Значение параметра | Строка, число, булево, дата или ссылка на справочник, документ, перечисление |

Какие параметры нужны, знает процедура. Кнопка "Получить параметры" спрашивает у процедур подготовки и обработки запроса список их параметров и добавляет недостающие строки. Уже заполненные строки кнопка не меняет. Перед нажатием запишите элемент и укажите процедуры.

## Настройка соответствий

Таблица на закладке "Настройка соответствий" сопоставляет значения внешней системы значениям базы: код вида документа во внешней системе - вид документа в базе, код склада - склад.

| Колонка | Назначение |
|---|---|
| Тип | Что сопоставляется, например `ВидДокумента` или `Склад`. Типы определяет процедура обработки |
| Ключ | Значение во внешней системе, например `INV` |
| Значение | Значение в базе: элемент справочника, перечисление, строка, число |

Пример для приема документов, где тип документа во внешней системе задает вид и папку документа в базе:

| Тип | Ключ | Значение |
|---|---|---|
| ВидДокумента | `INV` | Счет |
| Папка | `INV` | Входящие счета |
| ВидДокумента | `ACT` | Акт |
| Папка | `ACT` | Акты |


Кнопка "Получить параметры" может добавить и заготовки строк соответствий с пустым ключом, если процедура их предлагает. Ключ и значение в заготовках заполните сами.

## Доступность

Закладка "Доступность" позволяет передать настройку запроса пользователям без прав администратора обмена, например аналитику, который ведет соответствия.

| Колонка | Назначение |
|---|---|
| Пользователь | Пользователь базы |
| Просмотр | Пользователь видит запрос в списке и может открыть его |
| Редактирование | Пользователь может изменять запрос |

Ограничения действуют для пользователей с ролью "Настройки интеграции базовые права (МС)". Таким пользователям форма показывает только наименование и закладки "Значения параметров" и "Настройка соответствий": тип обмена, процедуры, способ получения данных, уведомления и доступность скрыты. Пользователи с ролью "Основная роль (МС)" или полными правами видят и изменяют все запросы.

## Перенос настроек между базами

Команды формы "Сохранить настройки в файл" и "Загрузить настройки из файла" переносят настройку запроса через XML-файл, например из тестовой базы в рабочую.

- В файл попадают все реквизиты и табличные части элемента, кроме кода и наименования.
- Загруженные настройки заполняют открытую форму. Проверьте их и запишите элемент.
- Ссылки на элементы справочников (в значениях параметров, соответствиях, доступности) переносятся по уникальному идентификатору. Если в базе-приемнике таких элементов нет, ссылки окажутся битыми: выберите значения заново.

## Процедуры подготовки и обработки

Раздел для разработчиков. Процедуры размещаются в общем модуле с флажком "Сервер" (конфигурации или расширения) и экспортируются. Сигнатура обеих процедур одинаковая:

```
Процедура ОбработатьЗаказы(НастройкиСинхронизации, СтруктураПараметров, РезультатЗапроса, РезультатЗагрузки) Экспорт
```

| Параметр | Содержимое |
|---|---|
| `НастройкиСинхронизации` | `СправочникСсылка.МС_НастройкиСинхронизации` - выполняемая настройка синхронизации |
| `СтруктураПараметров` | Параметры обмена, см. ниже |
| `РезультатЗапроса` | Процедуре обработки загрузки - результат запроса к источнику (массив файлов, сообщений, результат кода). Процедуре подготовки не передается |
| `РезультатЗагрузки` | Массив выгрузки: общий для всех строк одного запуска. Процедуре обработки выгрузки - результат отправки |

### Порядок вызова

Строки настройки синхронизации выполняются по порядку. Для каждой строки:

1. Вызывается процедура подготовки данных. Она может отказаться от выполнения запроса.
2. Загрузка: выполняется запрос к источнику. Если результат не `Неопределено`, вызывается процедура обработки с этим результатом.
3. Выгрузка: массив выгрузки передается в запрос (`СтруктураПараметров.РезультатВыгрузки`) и отправляется. Затем вызывается процедура обработки, четвертым параметром - результат отправки.

Массив выгрузки - один на весь запуск. Через него строки передают данные друг другу: процедура обработки загрузки добавляет в массив ответы, строка выгрузки ниже по таблице их отправляет. Поэтому строка выгрузки должна стоять в настройке синхронизации после строк, которые готовят для нее данные.

### Структура параметров

`СтруктураПараметров` содержит:

| Поле | Содержимое |
|---|---|
| Все реквизиты запроса | По именам реквизитов: `ТипОбмена` (0 - загрузка, 1 - выгрузка), `СпособЗапросаДанных`, `КаталогФайлов`, `ИмяОчереди`, `ТекстЗапроса` и другие |
| `НастройкаЗагрузки` | `СправочникСсылка.МС_ЗапросыКВнешнимИсточникам` - выполняемый запрос |
| `НастройкаСинхронизации` | Выполняемая настройка синхронизации |
| `Соединение` | Настройка подключения из настройки синхронизации |
| `НачалоПериода`, `ОкончаниеПериода` | Период синхронизации |
| `ЗначенияПараметров` | `ТаблицаЗначений` с колонками `ИмяПараметра`, `ЗначениеПараметра` |
| `НастройкаСоответствий` | `ТаблицаЗначений` с колонками `Тип`, `Ключ`, `Значение` |
| `МассивСсылок` | Выделенные строки списка, если обмен запущен командой "... выделенных строк" на форме объекта |
| `РезультатВыгрузки` | При выгрузке - массив выгрузки |
| `КонтекстЖурналаОбмена` | Служебное: общий идентификатор запуска для журнала обмена |

Процедуры могут добавлять в структуру свои поля: структура живет в пределах одной строки настройки синхронизации.

### Чтение параметров и соответствий

```
КаталогАрхива = МС_СинхронизацияСервер.ЗначениеПараметра(СтруктураПараметров.ЗначенияПараметров, "КаталогАрхива");
ВидыДокументов = МС_СинхронизацияСервер.СоответствиеИзТаблицыСоответствий("ВидДокумента", СтруктураПараметров.НастройкаСоответствий);
ВидДокумента = ВидыДокументов.Получить(КодТипаИзВнешнейСистемы);
```

Для групп связанных типов (вид документа, папка и шаблон по одному ключу) есть функции `МС_СинхронизацияСервер.ГруппаСоответствийПоКлючам`, `ОшибкиГруппыСоответствий` (проверка, что для каждого ключа заполнены все типы группы) и `ЗаготовкиГруппыСоответствий` (заготовки строк для кнопки "Получить параметры").

### Кнопка "Получить параметры"

Кнопка вызывает обе процедуры запроса с флагом `СтруктураПараметров.ТолькоДляЗаполненияЗначенийПараметров = Истина` и текущей таблицей соответствий в `СтруктураПараметров.ТекущаяНастройкаСоответствий`. В этом режиме процедура не обращается к данным, а только описывает свои параметры и выходит:

```
Если СтруктураПараметров.Свойство("ТолькоДляЗаполненияЗначенийПараметров") Тогда
	ЗначенияПараметров = Новый Структура;
	ЗначенияПараметров.Вставить("КаталогАрхива", "");
	ЗначенияПараметров.Вставить("Склад", Справочники.Склады.ПустаяСсылка());
	СтруктураПараметров.Вставить("ЗначенияПараметров", ЗначенияПараметров);
	Возврат;
КонецЕсли;
```

Ключ - имя параметра, значение - значение по умолчанию: его тип определяет, что пользователь сможет выбрать в строке. Для заготовок соответствий процедура помещает в `СтруктураПараметров.НастройкаСоответствий` таблицу значений с колонками `Тип`, `Ключ`, `Значение`. Форма добавит строки, которых в таблице еще нет.

### Отказ от выполнения

Процедура подготовки может отменить запрос, например если не заполнены обязательные параметры:

```
СтруктураПараметров.Вставить("Отказ", Истина);
СтруктураПараметров.Вставить("ТекстОтказа", "Не заполнен параметр ""КаталогАрхива"" на закладке ""Значения параметров"".");
```

Запрос и процедура обработки этой строки не выполняются, остальные строки запуска выполняются. В журнал обмена пишется ошибка "Запрос "..." не выполнен. <текст отказа>" с операцией `Конвейер`. Для RabbitMQ это значит, что сообщения остаются в очереди.

### Журнал обмена

Процедуры пишут историю обмена в журнал обмена:

```
МС_ЖурналОбменаСервер.ДобавитьЗапись(СтруктураПараметров, Перечисления.МС_УровниЖурналаОбмена.Информация,
	"Загружен заказ " + НомерЗаказа, "Заказы.Прием", ТекстСообщения);
```

Параметры: структура параметров (из нее берутся настройка синхронизации, запрос и идентификатор запуска), уровень, текст записи, операция (произвольная строка, по ней удобно отбирать записи) и данные сообщения (текст как есть, например JSON). Запись выполняется в привилегированном режиме.

### Где выполняется код

Процедуры выполняются на сервере. При обмене по расписанию - в привилегированном режиме. При запуске кнопкой "Выполнить обмен" или командой на форме объекта - с правами пользователя, который запустил обмен.

## Ошибки

Ошибка, не перехваченная в процедуре или в запросе, записывается в журнал обмена с уровнем "Ошибка" и операцией `Конвейер`: "Ошибка выполнения запроса ...: <подробное описание>". После этого запуск прерывается: следующие строки настройки синхронизации не выполняются.

Типовые ошибки:

| Ошибка | Причина |
|---|---|
| "Каталог ... не существует" | Не найден один из каталогов сохранения при включенном копировании |
| "Не задано имя очереди" | Не заполнено поле "Имя очереди" для способа RabbitMQ |
| "Ошибка чтения очереди" с кодом 401 | Неверный логин или пароль RabbitMQ в настройке подключения |
| "Ошибка чтения очереди" с кодом 404 | Нет такой очереди или неверный виртуальный хост |
| "Сообщение не доставлено: очереди с таким именем нет или она недоступна" | Точка обмена не доставила сообщение ни в одну очередь |
| Ошибка вызова процедуры | Процедура не найдена, не экспортирована, модуль не серверный или ошибка в имени |
