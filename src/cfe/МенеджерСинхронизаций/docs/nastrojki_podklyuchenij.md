## Общее описание

Справочник "Настройки подключений (МС)" (`МС_НастройкиПодключений`) хранит адрес, учетные данные и параметры соединения с внешним источником: HTTP-сервером, FTP-сервером или источником, к которому подключается код на встроенном языке. Одну настройку используют несколько настроек синхронизации: адрес и пароль меняются в одном месте.

Устройство:

- **Настройка подключения** указывается в поле "Соединение" настройки синхронизации. Все запросы этой синхронизации работают через нее.
- **Объект соединения** создается по настройке при каждом запуске обмена: `HTTPСоединение` для HTTP, `FTPСоединение` для FTP.
- **Пароли** хранятся в безопасном хранилище БСП, а не в реквизитах справочника.

## Виды подключения

Вид выбирается переключателем "Вид подключения" в шапке. От него зависит набор полей ниже.

| Вид | Для чего | Объект соединения |
|---|---|---|
| HTTP | REST API, веб-сервисы, RabbitMQ Management API | `HTTPСоединение` |
| FTP | Обмен файлами с FTP- и FTPS-серверами | `FTPСоединение` |
| Произвольное | Соединение, которое создает код на встроенном языке: COM-объект, ADO, внешняя компонента | Любой объект, созданный кодом |

Новая настройка создается с видом "Произвольное": сначала выберите нужный вид.

## HTTP

| Поле | Назначение |
|---|---|
| Сервер | Адрес сервера со схемой, например `https://api.example.com`. Может содержать порт и путь: `https://api.example.com:8443/v2` |
| Порт | Пусто - порт из адреса, иначе 443 для `https://` и 80 для `http://`. Порт, указанный в адресе, важнее значения поля |
| Пользователь, Пароль | Basic-авторизация: платформа сама добавляет заголовок `Authorization: Basic ...`. Пусто - запросы без авторизации |
| Таймаут | Время ожидания ответа в секундах. `0` или пусто - без ограничения |
| Использовать SSL | Защищенное соединение. Для адреса со схемой `https://` включается автоматически |
| Использовать прокси, Прокси сервер, Прокси порт, Прокси пользователь | Прокси-сервер для HTTP, HTTPS и FTP. Порт прокси по умолчанию 8080 |
| Заголовки | HTTP-заголовки, которые добавляются к каждому запросу через эту настройку |

**Путь в адресе.** Часть адреса после хоста (`/v2` в примере выше) называется базовым путем. Его используют способы обмена и обработчики: например, транспорт RabbitMQ строит адреса очередей от базового пути. Кнопка "Проверить соединение" обращается именно к нему.

**Заголовки.** Одна строка таблицы - один заголовок. Здесь задается авторизация, отличная от Basic, и общие заголовки:

| Имя заголовка | Значение |
|---|---|
| `Authorization` | `Bearer eyJhbGciOi...` |
| `X-Api-Key` | `abc123` |
| `Accept` | `application/json` |

Значения заголовков хранятся в базе в открытом виде, в отличие от пароля.

**Перенаправления.** Если сервер отвечает перенаправлением (коды 301, 302, 303, 307, 308), запрос повторяется по новому адресу, не более 10 раз. При переходе на другой сервер логин, пароль и заголовки `Authorization` и `Cookie` не передаются. Поэтому в поле "Сервер" лучше указывать конечный адрес, без перенаправлений.

## FTP

| Поле | Назначение |
|---|---|
| Сервер | Имя хоста или IP-адрес без протокола, например `ftp.example.com`. Префикс `ftp://` или `ftps://` отбрасывается |
| Порт | Пусто - 21 |
| Пользователь, Пароль | Учетные данные FTP |
| Таймаут | Время ожидания ответа в секундах. `0` или пусто - без ограничения |
| Использовать SSL | Защищенное соединение FTPS (FTP over TLS) |
| Пассивный режим | Клиент сам открывает соединение для передачи данных. Обычно включен: так обмен проходит через NAT и большинство сетевых экранов |
| Уровень защищенного соединения | Как применять защиту: "Требовать для управления" (по умолчанию, в том числе при пустом значении), "Требовать", "Использовать, если возможно", "Авто", "Не использовать". Действует при включенном "Использовать SSL" |
| Основной каталог | Каталог на сервере, от которого отсчитываются пути файлов, например `/data`. Пусто - пути используются как есть |
| Использовать прокси, Прокси сервер, Прокси порт, Прокси пользователь | Прокси-сервер для подключения. Порт прокси по умолчанию 8080 |

**Основной каталог.** Полезен, когда внешняя система передает пути файлов от своего корня, а на сервере они лежат в подкаталоге: путь `/2026/01/file.pdf` при основном каталоге `/data` превращается в `/data/2026/01/file.pdf`. Основной каталог применяют обработчики, которые строят пути функцией `ПолныйПутьFTP` (см. [Использование в коде](#использование-в-коде)). Способ получения данных "Файлы с FTP" в запросах к внешним источникам работает с каталогом, указанным в самом запросе.

Если сервер не принимает подключение с уровнем защиты по умолчанию, попробуйте "Авто": так подключаются, например, FTPS-шлюзы объектных хранилищ.

## Произвольное подключение

Соединение создает код на встроенном языке. Подходит для источников, которые не подключаются по HTTP или FTP, например для баз данных через ADO.

| Поле | Назначение |
|---|---|
| Пользователь, Пароль | Учетные данные, доступные коду через `Настройка.Пользователь` и `Настройка.Пароль` |
| Строка подключения | Выражение на встроенном языке. Вычисляется первым, результат доступен коду в переменной `СтрокаПодключения` |
| Код подключения | Код на встроенном языке. Должен присвоить объект соединения переменной `Соединение` |

Пример подключения к SQL Server через ADO:

Строка подключения:

```
"Provider=SQLOLEDB;Data Source=sql01;Initial Catalog=Sales;User ID=" + Настройка.Пользователь + ";Password=" + Настройка.Пароль
```

Код подключения:

```
Соединение = Новый COMОбъект("ADODB.Connection");
Соединение.Open(СтрокаПодключения);
```

Код выполняется на сервере, при регламентном обмене - в привилегированном режиме. Давайте право изменять такие настройки только администраторам.

## Пароль

Поле "Пароль" есть на страницах всех видов и хранит одно значение. Пароль записывается в безопасное хранилище при записи настройки.

- Пароль сохраняется, только если поле заполнено. Запись настройки с пустым полем не стирает сохраненный пароль.
- Пароль привязан к элементу справочника. При копировании настройки пароль не копируется: введите его в копии заново.


## Проверка соединения

Кнопка "Проверить соединение" обращается к серверу по сохраненной настройке. Если на форме есть незаписанные изменения, она попросит сначала записать элемент.

Для HTTP выполняется запрос `GET` по адресу из поля "Сервер", включая путь:

| Результат | Что означает |
|---|---|
| "Соединение установлено: GET ... вернул код 200" | Адрес и авторизация верны |
| "... доступен, но отклонил авторизацию (код 401 или 403)" | Сервер найден, проверьте пользователя, пароль и заголовки |
| "... доступен, ответил RabbitMQ Management API (код 404 "Object Not Found")" | Адрес указывает на корень RabbitMQ Management API. Это верная настройка для обмена через RabbitMQ: у корня API нет метода, поэтому сервер отвечает 404. Логин и пароль этой проверкой не проверяются |
| "... доступен, но вернул код ..." | Сервер ответил, но не на этот путь. В сообщении есть начало ответа: по нему видно, кто ответил, приложение или прокси перед ним |
| "... недоступен: ..." | Сервер не ответил: неверный адрес или порт, нет сети, ошибка защищенного соединения |
| "Перенаправления: ... -> ..." | Сервер перенаправил запрос. Укажите в поле "Сервер" конечный адрес |

Для FTP запрашивается текущий каталог сервера: "Соединение установлено, текущий каталог FTP: ..." означает, что сервер, порт, SSL и учетные данные верны. Если заполнен основной каталог, дополнительно проверяется, что он доступен, и выводится число файлов и каталогов в нем.

Для произвольного подключения проверяется только то, что код выполнился без ошибок. Обращение к источнику не проверяется.

## Использование в коде

Раздел для разработчиков обработчиков обмена.

`Справочники.МС_НастройкиПодключений.ПолучитьСоединение(НастройкаПодключения)` возвращает структуру:

| Поле | Содержимое |
|---|---|
| `Соединение` | `HTTPСоединение`, `FTPСоединение` или объект произвольного подключения. `Неопределено` при ошибке |
| `СтрокаОшибок` | Текст ошибки создания соединения, пустая строка при успехе |
| `Заголовки` | Соответствие заголовков из таблицы "Заголовки" (только HTTP) |
| `БазовыйПуть` | Путь из адреса сервера без завершающего `/`, например `/v2` (только HTTP) |
| `ОсновнойКаталогFTP` | Основной каталог вида `/data` или пустая строка (только FTP) |

Создание `HTTPСоединение` не обращается к серверу: ошибки адреса и авторизации проявятся при первом запросе.

HTTP-запросы удобно выполнять функцией `МС_ПодключенияСервер.ВыполнитьHTTPЗапрос(СтруктураСоединения, Метод, Ресурс, ДополнительныеЗаголовки, Тело)`. Она подставляет заголовки настройки, выполняет перенаправления и возвращает структуру с полями `КодСостояния`, `Заголовки`, `Тело`, `ТелоТекст`, `СтрокаОшибок`, `ИтоговыйАдрес`, `ЦепочкаАдресов`. Базовый путь функция не подставляет: ресурс собирает вызывающий код.

```
СтруктураСоединения = Справочники.МС_НастройкиПодключений.ПолучитьСоединение(НастройкаПодключения);
Ответ = МС_ПодключенияСервер.ВыполнитьHTTPЗапрос(СтруктураСоединения, "GET",
	СтруктураСоединения.БазовыйПуть + "/orders?status=new");
Если Ответ.КодСостояния = 200 Тогда
	Заказы = МС_ПодключенияСервер.ПрочитатьОтветJSON(Ответ);
КонецЕсли;
```

Другие функции:

- `МС_ПодключенияСервер.ПрочитатьОтветJSON(Ответ)` и `ПрочитатьОтветXML(Ответ)` разбирают тело ответа;
- `Справочники.МС_НастройкиПодключений.ПолныйПутьFTP(ОсновнойКаталогFTP, Путь)` строит путь файла на FTP с учетом основного каталога;
- `Справочники.МС_НастройкиПодключений.ПроверитьСоединение(НастройкаПодключения)` выполняет ту же проверку, что кнопка "Проверить соединение", и возвращает структуру `Успешно`, `Текст`.
