## Общее описание

Справочник "Настройки API (МС)" (`МС_НастройкиAPI`) описывает методы HTTP API базы: по какому адресу метод доступен, какие данные он отдает и какие параметры принимает. Один элемент справочника - один метод (адрес + HTTP-метод). Для базовой настройки код писать не нужно: данные выбираются конструктором или текстом запроса, для сложных случаев есть программный модуль.

Устройство:

- **HTTP-сервис** `МС_HTTPAPI` с корневым URL `sm` и шаблоном URL `УниверсальныйШаблон` (`/{Версия}/{ПараметрURL}/*`) принимает все вызовы и передает их в общий модуль `МС_HTTPAPIСервер`.
- **Настройка** выполняется поиск по версии, параметру URL (без учета регистра) и HTTP-методу. Помеченные на удаление настройки не участвуют.
- **Ответ** - JSON или XML вида `{"apiVersion": ..., "data": [...]}`.

## Адрес метода

```
<адрес публикации базы>/hs/sm/<Версия API>/<Параметр URL>[/<хвост пути>][?параметры]
```

Пример: `https://docs.example.ru/docmng/hs/sm/v1/counterparties?inn=7701234567`.

Итоговый адрес показан на форме элемента в поле под шапкой и пересчитывается при изменении метода, версии, параметра URL и параметров запроса. Адрес публикации берется из настроек администрирования ("Адрес публикации в локальной сети", затем "в Интернете", затем адрес веб-клиента). Если ни один не задан, вместо него выводится `http://<сервер>/<публикация>`.

Для GET, HEAD, DELETE и OPTIONS в адрес добавляются параметры со значениями из таблицы "Тестовые значения" - такой адрес можно сразу открыть в браузере. Для POST, PUT и PATCH параметры передаются в теле, поэтому адрес показан без них.

Вызов выполняется от имени пользователя информационной базы, указанного при подключении к публикации (обычно Basic-аутентификация). Данные выбираются с правами этого пользователя.

## Шапка элемента

| Поле | Назначение |
|---|---|
| Наименование | Произвольное описание метода |
| Активно | Выключено - метод отвечает `503 Сервис временно недоступен`. Новые настройки создаются выключенными: включите после проверки |
| HTTP-метод | GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS |
| Версия | Первый сегмент адреса, например `v1`. До 3 символов |
| Параметр URL | Второй сегмент адреса, например `counterparties`. До 50 символов |

Версия и параметр URL - части адреса, поэтому в них нельзя использовать `/ \ ? # & % =` и пробелы. Сочетание "версия + параметр URL + HTTP-метод" должно быть уникальным (регистр букв не различается): на один адрес можно повесить, например, GET и POST, но не два GET.

## Способы получения данных

Способ выбирается в поле "Способ получения данных" на закладке "Получение данных". Под ним показываются только поля выбранного способа. На закладке "Параметры HTTP и сериализация" от способа зависят команды и колонки таблицы "Параметры запроса": "Заполнить из текста запроса" есть только у текста запроса, "Заполнить из отборов" и запрет ручного ввода имени и типа параметра - только у конструктора, колонка "Источник" - только у программного модуля. "Лимит строк" не используется программным модулем и для него скрыт.

### Конструктор

Запрос строится по таблице, выбранной в мастере, без написания текста. Навыки программирования не нужны: метод может настроить аналитик или оператор.

1. **Тип источника**: справочник, документ, регистр сведений или план видов характеристик.
2. **Объект метаданных** - из списка. Для справочника и документа можно выбрать **табличную часть**; поле "Итоговое имя таблицы запроса" покажет, например, `Справочник.ВходящиеДокументы`.
3. **Виртуальная таблица** - только для периодического регистра сведений:
   - **Основная таблица** - все записи регистра;
   - **Срез последних** - последнее значение по каждому набору измерений на дату, например курс каждой валюты на дату;
   - **Срез первых** - первое значение по каждому набору измерений после даты.

   Для среза укажите **Параметр периода** - имя параметра вызова с датой среза, например `date`. Параметр сам попадает в таблицу "Параметры запроса" с типом `ДАТА`. Если параметр не передан или не указан, срез строится на текущий момент. Дата передается в формате `2024-01-31` или `2024-01-31T10:00:00`.
4. **Поля ответа**: таблица заполняется полями объекта - реквизитами и стандартными полями (Ссылка, Пометка удаления; Код и Наименование у справочников; Дата, Номер и Проведен у документов; Период у периодических регистров сведений). Отметьте те, что попадут в ответ.
   - **Имя в ответе** - имя свойства в JSON (или элемента в XML), например `registrationNumber`. Допустимы буквы, цифры и подчеркивание, первый символ - буква; имена не должны повторяться. Если не заполнено, используется имя поля 1С, к которому для формата "Код" добавляется `Код`, а для формата "Реквизит" - имя реквизита: `КонтрагентКод`, `КонтрагентИНН`.
   - **Формат** - как вывести поле-ссылку. Для полей других типов (строка, число, дата) формат не влияет.

     | Формат | Что выводится | Пример |
     |---|---|---|
     | Представление | Текстовое представление ссылки | `"ООО Ромашка"` |
     | Идентификатор | УИД ссылки строкой; для перечисления - имя значения; пустая ссылка - `null` | `"7c9e6679-7425-40de-944b-e07fc1f90ae7"` |
     | Код | Код справочника или плана видов характеристик, номер документа; для перечисления - имя значения | `"000000123"` |
     | Реквизит | Значение реквизита из колонки "Реквизит" | `"7701234567"` (ИНН) |

   - **Реквизит** - для формата "Реквизит": реквизит объекта, на который ссылается поле. Кнопка выбора показывает реквизиты типа поля, например для поля "Контрагент" - ИНН, КПП, Наименование полное.
   - Одно поле можно добавить несколькими строками с разными форматами. Например, для заказов клиентов поле "Контрагент" тремя строками: идентификатором (`partnerId`), представлением (`partner`) и реквизитом ИНН (`partnerInn`).
   - Строку можно добавить вручную и выбрать поле из списка или ввести путь через точку, например `Отправитель.ИНН`.
   - Кнопка "Заполнить поля из метаданных" обновляет список, сохраняя отметки, имена в ответе, форматы, реквизиты и добавленные вручную поля. Если не отмечено ни одно поле, в ответе будет только `Ссылка`.
5. **Отборы (условия ГДЕ)** - какие строки попадут в ответ. Каждая строка таблицы - условие "Поле Сравнение Значение":

   | Колонка | Назначение |
   |---|---|
   | Поле | Поле таблицы, по которому отбираются строки |
   | Сравнение | `=`, `<>`, `>`, `<`, `>=`, `<=`, `ПОДОБНО` |
   | Параметр запроса | Имя параметра вызова, значение которого передает клиент, например `currency`. Параметр сам попадает в таблицу "Параметры запроса" с типом поля. Если необязательный параметр не передан, отбор не применяется |
   | Фиксированное значение | Постоянное значение отбора, которое клиент API изменить не может, например "Пометка удаления = Ложь". Кнопка выбора открывает ввод значения по типу поля (для ссылок - выбор элемента), значение можно ввести и текстом в ячейке |

   Фиксированное значение важнее параметра. Если в строке задано и то, и другое, действует фиксированное значение, а параметр очищается и не попадает в "Параметры запроса". Так можно ограничить данные, которые отдает метод: отбор "Валюта = RUB" с фиксированным значением выдает только курс рубля, и клиент API не получит курс USD, даже если передаст `currency=USD` для другого отбора по валюте - условия отборов складываются через И.

   Обязательность параметров отборов и способ поиска ссылки по переданной строке настраиваются на закладке "Параметры HTTP и сериализация", см. [Параметры запроса](#параметры-запроса).

Таблицы мастера существуют только на форме. При записи элемента они сохраняются в реквизиты справочника: `КонструкторИмяТаблицы` (полное имя таблицы), `КонструкторВиртуальнаяТаблица` и `КонструкторПараметрПериода` (срез регистра), `КонструкторПоля` и `КонструкторОтборыJSON` (поля и отборы в формате JSON). По этим реквизитам HTTP-сервис строит запрос при вызове; на форме они не показываются.

### Текст запроса

Данные выбирает запрос на языке запросов 1С из поля "Текст запроса". Используется, когда выборку не описать конструктором: соединения таблиц, группировки, вычисляемые поля. Требует знания языка запросов.

Каждый параметр `&Имя` из текста должен быть описан в таблице "Параметры запроса" - кнопка "Заполнить из текста запроса" добавит недостающие (у уже описанных параметров сохраняются отметка "Обязательный", тип и подсказка). Расхождение текста и таблицы не даст записать элемент.

Параметр `&ЛимитСтрок` описывать не нужно: он всегда равен значению поля "Лимит строк".

Если необязательный параметр не передан, в запрос подставляется `Неопределено`. Необязательный отбор записывается так:

```
ГДЕ
	(&inn = НЕОПРЕДЕЛЕНО ИЛИ Контрагенты.ИНН = &inn)
```

### Программный модуль

Для логики, которую не выразить запросом. Обработчик пишет разработчик.

Данные возвращает функция `ВыполнитьОбработчик` общего модуля `МС_HTTPAPIПользовательскиеОбработчики`. В поле "Имя метода обработчика" указывается имя, по которому функция выбирает нужную ветку. Функция получает:

- `Параметры.Параметры` - соответствие параметров вызова, приведенных к типам из "Параметров запроса";
- `Параметры.ХвостПути` - часть адреса после параметра URL: для `/v1/orders/123/items` это `123/items`.

Функция возвращает массив структур, структуру или примитив - они попадут в `data`. Если для имени метода нет ветки, вызов завершается ошибкой "Обработчик API ... не найден". Модуль входит в расширение, поэтому новые обработчики добавляются его доработкой.

## Параметры запроса

Таблица "Параметры запроса" на закладке "Параметры HTTP и сериализация" описывает параметры, которые принимает метод. В конструкторе строки создаются по отборам и параметру периода, имя и тип параметра меняются только там. В тексте запроса строки создает кнопка "Заполнить из текста запроса".

| Колонка | Назначение |
|---|---|
| Имя в запросе | Имя параметра в строке запроса или в теле |
| Обязательный | Включено - вызов без параметра отклоняется с ошибкой 400. Выключено - параметр необязательный: отбор конструктора по нему не применяется, в тексте запроса он равен `Неопределено` |
| Тип значения | Тип для приведения строкового значения (см. ниже). В конструкторе заполняется по полю отбора |
| Сопоставление строки | Для параметров отборов конструктора по полю-ссылке: как искать ссылку по переданной строке (см. ниже) |
| Источник | Справочно, для программного модуля |
| Подсказка | Описание параметра для потребителей API |

Имена параметров рекомендуется задавать латиницей: они видны потребителям API в адресе и теле запроса.

Строковое значение параметра для поля-ссылки ищется так, как задано в колонке "Сопоставление строки":

| Сопоставление | Как ищется ссылка |
|---|---|
| Авто | По УИД, затем по коду (номеру документа), затем по наименованию |
| Идентификатор | Только по УИД |
| Код | По коду справочника или номеру документа |
| Наименование | По наименованию (для перечислений - по имени или синониму значения) |

Пустая строка означает пустую ссылку. Если значение не найдено, отбор не вернет ни одной строки.

Значение из адреса приходит строкой и приводится к типу из колонки "Тип значения": `ЧИСЛО`, `БУЛЕВО` (`true`/`false`, `1`/`0`, `да`/`нет`), `ДАТА` (`2024-01-31` или `2024-01-31T10:00:00`), `УИД`. Для `СТРОКА` и пустого типа значение передается как есть. Значения из JSON-тела, уже имеющие тип (число, булево), не меняются.

Где можно передать параметр:

- в строке запроса: `?inn=7701234567&code=000000123`;
- в теле JSON-объектом: `{"inn": "7701234567"}`.

При совпадении имен значение из тела заменяет значение из строки запроса. Пустая строка считается непереданным значением, а `false` и `0` из JSON - переданными.

## Формат ответа

Группа "Ответ и сериализация" на закладке "Параметры HTTP и сериализация".

| Поле | Назначение |
|---|---|
| Формат ответа | JSON или XML (корневой элемент `root`, элементы массива - `item`) |
| Лимит строк | Максимум строк в ответе, `0` - без ограничения. Для конструктора и текста запроса; в тексте запроса доступен как параметр `&ЛимитСтрок` |
| Формат дат (JSON) | ISO 8601 - `"2024-01-31T10:00:00"`, время сервера. Unix-время - число секунд от 01.01.1970 UTC. Пустая дата выводится как `null`. По умолчанию ISO 8601 |
| Перенос строк, Символы отступа | Форматирование JSON. Для читаемого ответа задайте перенос "Авто" и отступ из двух пробелов |
| Экранирование символов | Нет - только обязательное экранирование; СимволыВнеASCII или СимволыВнеBMP - дополнительно кодировать такие символы как `\uXXXX` |
| Флажки экранирования | `<` и `>`, разделители строк, `&`, одинарные кавычки, слеш `/` |

В тексте запроса и программном модуле ссылки и значения перечислений выводятся представлением ("ООО Ромашка"). В конструкторе вывод ссылки задает колонка "Формат" поля ответа: представление, идентификатор, код или реквизит. `NULL` и `Неопределено` в JSON выводятся как `null`.

Ответ содержит заголовки `Content-Type` (`application/json` или `application/xml`, `charset=utf-8`) и `API-Version`.

## Проверка

Закладка "Проверка и пример ответа".

1. Заполните таблицу "Тестовые значения" (строки создаются по "Параметрам API"). Пустое значение - параметр не передан.
2. Запишите элемент.
3. Нажмите "Тест" - настройка выполняется так же, как HTTP-вызов, с тестовыми значениями; результат или текст ошибки появится в поле под таблицей. "Сформировать пример" выполняет настройку без параметров.

Обе команды работают по сохраненной настройке: если на форме есть незаписанные изменения, они попросят сначала записать элемент. Отметка "Активно" на тест не влияет.

Последний шаг - вызов из браузера. Скопируйте адрес из поля "Адрес API", например:

```
https://docs.example.ru/docmng/hs/sm/v1/counterparties?inn=7701234567
```

Откройте его в браузере. На запрос логина и пароля введите учетные данные пользователя информационной базы, от имени которого работает внешняя система. Браузер покажет ответ JSON или XML.

Так проверяются только GET-методы: браузер при открытии адреса отправляет GET. Методы POST, PUT, PATCH и DELETE проверяются кнопкой "Тест" или программой для HTTP-запросов, например Postman.

## Ошибки

| Код | Когда | Сообщение (`error.message`) |
|---|---|---|
| 400 | Не передан обязательный параметр; тело начинается с `{`, но не является JSON | `Не передан обязательный параметр: inn` |
| 404 | Нет настройки для этой версии, параметра URL и HTTP-метода | `Настройка API не найдена` |
| 500 | Ошибка выполнения: ошибка в тексте запроса, неизвестный обработчик, поле или реквизит конструктора не найден, параметр периода среза не является датой | Краткое описание ошибки |
| 503 | Настройка выключена (снят флажок "Активно") | `Сервис временно недоступен` |

Тело ошибки:

```json
{"error": {"code": "400", "message": "Не передан обязательный параметр: inn"}, "apiVersion": "v1"}
```

Ошибки 500 записываются в журнал регистрации с событием `МенеджерСинхронизаций.HTTP API` и подробным описанием ошибки.

## Примеры

### Пример 1. Входящие документы контрагента за период (конструктор)

| Поле | Значение |
|---|---|
| HTTP-метод, Версия, Параметр URL | GET, `v1`, `incoming` |
| Способ получения данных | Конструктор |
| Тип источника, Объект | Справочник, Входящие документы |

| Поле | Сравнение | Параметр запроса | Фиксированное значение |
|---|---|---|---|
| Отправитель | = | `sender` | |
| ДатаРегистрации | >= | `from` | |
| ДатаРегистрации | < | `to` | |
| ПометкаУдаления | = | | Ложь |

После записи в "Параметрах запроса" будут `sender` (тип `ССЫЛКА`), `from` и `to` (тип `ДАТА`). Отметьте `sender` обязательным, сопоставление "Авто". `from` и `to` оставьте необязательными: без них отбор по дате не применяется.

```
GET .../hs/sm/v1/incoming
```

### Пример 2. Поиск контрагентов (текст запроса)

| Поле | Значение |
|---|---|
| HTTP-метод, Версия, Параметр URL | GET, `v1`, `counterparties` |
| Способ получения данных | Текст запроса |
| Формат ответа, Формат дат | JSON, ISO 8601 |

Текст запроса:

```
ВЫБРАТЬ ПЕРВЫЕ 100
	Контрагенты.Наименование КАК name,
	Контрагенты.ИНН КАК inn,
	Контрагенты.КПП КАК kpp,
	Контрагенты.ЮрФизЛицо КАК legalType
ИЗ
	Справочник.Контрагенты КАК Контрагенты
ГДЕ
	НЕ Контрагенты.ПометкаУдаления
	И (&inn = НЕОПРЕДЕЛЕНО ИЛИ Контрагенты.ИНН = &inn)
	И (&name = НЕОПРЕДЕЛЕНО ИЛИ Контрагенты.Наименование ПОДОБНО &name)
```

"Заполнить из текста запроса" создаст параметры `inn` и `name`. Оба оставьте необязательными, тип `СТРОКА`. Псевдонимы полей (`КАК name`) становятся именами свойств в ответе.


Во втором вызове `%25` - закодированный символ `%` для `ПОДОБНО`. Третий вызов вернет первых 100 контрагентов без отбора.

Ответ:


### Пример 3. Прием данных методом POST (программный модуль)

| Поле | Значение |
|---|---|
| HTTP-метод, Версия, Параметр URL | POST, `v1`, `status` |
| Способ получения данных | Программный модуль |
| Имя метода обработчика | `ОбновитьСтатусЗаявки` |
| Параметры запроса | `requestId` (обязательный, `СТРОКА`), `status` (обязательный, `СТРОКА`) |

В функцию `ВыполнитьОбработчик` модуля `МС_HTTPAPIПользовательскиеОбработчики` добавляется ветка: при `ИмяМетода = "ОбновитьСтатусЗаявки"` она берет значения из `Параметры.Параметры`, выполняет обработку и помещает в `Результат` структуру ответа, например `Новый Структура("result", "ok")`.

Вызов:

```
curl -u api_user:password -X POST -H "Content-Type: application/json" \
	-d "{\"requestId\": \"A-2024-0015\", \"status\": \"done\"}" \
	"https://docs.example.ru/docmng/hs/sm/v1/status"
```

Ответ: `{"apiVersion": "v1", "data": {"result": "ok"}}`.
