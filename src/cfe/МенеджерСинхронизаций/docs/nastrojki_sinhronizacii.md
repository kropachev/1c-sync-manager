## Общее описание

Справочник "Настройки синхронизации (МС)" (`МС_НастройкиСинхронизации`) собирает запросы к внешним источникам в один обмен: с каким источником работать, какие шаги выполнять и в каком порядке, когда запускать. Результат каждого запуска записывается в "Журнал обмена (МС)".

Устройство:

- **Настройка синхронизации** - один обмен: соединение с источником и упорядоченный список запросов.
- **Запуск** - по расписанию регламентного задания, кнопкой "Выполнить обмен" или командой на форме объекта базы.
- **Журнал обмена** (`МС_ЖурналОбмена`) - что получено и отправлено, предупреждения и ошибки по каждому запуску.

## Порядок настройки

1. "Менеджер синхронизаций (МС)" - "Настройки подключений (МС)": создать подключение к источнику и проверить его кнопкой "Проверить соединение".
2. "Запросы к внешним источникам (МС)": создать запросы - по одному на каждый шаг обмена.
3. "Настройки синхронизации (МС)": создать настройку, указать соединение и запросы, записать.
4. Нажать "Выполнить обмен" и проверить результат в "Журнале обмена (МС)".
5. Настроить расписание.

## Шапка элемента

| Поле | Назначение |
|---|---|
| Наименование | Уникальное имя обмена. Две настройки с одинаковым наименованием записать нельзя |
| Код | Присваивается при записи. По коду регламентное задание находит настройку: не меняйте его |
| Соединение | Настройка подключения, через которую работают все запросы этой синхронизации. Можно не заполнять, если запросам соединение не нужно (например, файлы из каталога) |

## Настройки загрузки

Таблица "Настройки загрузки" - шаги обмена. Строки выполняются по порядку.

| Колонка | Назначение |
|---|---|
| Активно | Выполнять строку. Снятый флажок временно отключает шаг без удаления |
| Настройка загрузки | Запрос к внешнему источнику |
| Полное имя формы | Формы объектов, на которых появится команда запуска этого шага|

**Порядок строк важен.** Строки одного запуска передают данные друг другу через общий массив выгрузки: например, строка приема обрабатывает входящие сообщения и готовит ответы, а строка отправки ниже публикует их. Строка выгрузки должна стоять после строк, которые готовят для нее данные.

**Ошибка прерывает запуск.** Если в строке произошла ошибка, она записывается в журнал обмена, а следующие строки не выполняются. Исключение - отказ процедуры подготовки: строка пропускается, следующие выполняются.

## Период синхронизации

Период передается в процедуры обработки и в код запроса (`НачалоПериода`, `ОкончаниеПериода`): например, загрузить документы за последнюю неделю. Если процедурам период не нужен, поля можно не заполнять.

**Фиксированный период** - поля "Период с" и "по". Окончание периода дополняется до конца дня.

**Вычисляемый период** - флажок "Вычисляемый период". Начало и окончание задаются выражениями на встроенном языке и вычисляются при каждом запуске:

| Период | Начало периода | Окончание периода |
|---|---|---|
| Вчера | `НачалоДня(ТекущаяДатаСеанса()) - 86400` | `НачалоДня(ТекущаяДатаСеанса()) - 1` |
| Последние 7 дней | `НачалоДня(ТекущаяДатаСеанса()) - 7 * 86400` | `КонецДня(ТекущаяДатаСеанса())` |
| Текущий месяц | `НачалоМесяца(ТекущаяДатаСеанса())` | `КонецМесяца(ТекущаяДатаСеанса())` |

Кнопка "Вычислить период" показывает результат выражений рядом с полями: так их удобно проверить до записи.

## Расписание

По расписанию обмен выполняется регламентным заданием "Запуск дополнительных обработок" (БСП) с наименованием "(МС) <наименование настройки>". Задание создается и обновляется при записи настройки.

1. Запишите новую настройку. При первой записи появится сообщение "Код настройки не записан в регламентном задании": у новой настройки еще нет кода, задание создается при следующей записи.
2. Нажмите "Настроить расписание обмена" и задайте расписание в стандартном диалоге, например каждые 60 секунд или ежедневно в 02:00.
3. Запишите настройку. После этого на кнопке показывается текущее расписание.

Задание выполняется в привилегированном режиме, поэтому права пользователя, под которым работает регламентное задание, не ограничивают обмен.

**Как остановить обмен по расписанию:**

- временно отключить шаги - снять флажки "Активно" у строк;
- остановить обмен целиком - пометить настройку на удаление: помеченные настройки по расписанию не выполняются;
- удалить настройку - вместе с ней удаляется регламентное задание.

При копировании настройки регламентное задание не копируется: у копии оно создается при записи.

## Запуск вручную

Кнопка "Выполнить обмен" на форме настройки или в списке запускает все активные строки. Обмен выполняется в фоне.

- Перед запуском запишите настройку: с незаписанными изменениями обмен не запускается.
- Обмен выполняется с правами текущего пользователя, а не в привилегированном режиме, как по расписанию.
- После завершения показываются сообщения фонового задания и текст ошибки, если обмен завершился аварийно. Подробный результат - в журнале обмена.

## Команды на формах объектов

Шаг обмена можно запускать прямо из формы объекта базы: например, загрузить остатки из внешней системы из формы списка номенклатуры.

1. В строке таблицы "Настройки загрузки" нажмите кнопку выбора в колонке "Полное имя формы".
2. Добавьте полные имена форм, например `Справочник.Номенклатура.Форма.ФормаСписка` или `Документ.ЗаказКлиента.Форма.ФормаДокумента`. Можно указать несколько форм.
3. Запишите настройку и откройте форму объекта заново.

На командной панели формы появится подменю "Синхронизация (МС)" с командами по строкам, в которых указана эта форма:

| Команда | Что делает |
|---|---|
| "<наименование запроса>" | Выполняет эту строку настройки синхронизации |
| "<наименование запроса> выделенных строк" | Выполняет эту строку настройки синхронизации и передает выделенные строки списка: процедуры обработки получают их в `СтруктураПараметров.МассивСсылок`. Для запросов с интерактивной загрузкой не показывается |

Команда выполняет только свою строку, остальные строки настройки не запускаются. Команды показываются пользователям с правом чтения настроек синхронизации, только для активных строк.

Команды добавляются через переопределяемый модуль `МодификацияКонфигурацииПереопределяемый`, который есть в современных конфигурациях 1С. Расширение заимствует этот модуль, поэтому он должен быть в конфигурации: без него расширение не подключится.

## Журнал обмена

"Менеджер синхронизаций (МС)" - "Журнал обмена (МС)". Одна запись - одно событие обмена.

| Колонка | Содержимое |
|---|---|
| Период | Время записи |
| Настройка синхронизации | Обмен, в котором произошло событие |
| Идентификатор запуска | Общий для всех записей одного запуска: по нему видно, что произошло за один запуск |
| Номер записи | Порядок записей внутри запуска |
| Сообщение | Описание события |
| Уровень | Информация, Предупреждение, Ошибка |
| Запрос | Запрос к внешнему источнику, в рамках которого сделана запись |
| Операция | Вид события, например `RabbitMQ.Получение` |

Справа от списка - "Данные сообщения" текущей записи: полученное или отправленное сообщение, тело ответа сервера. Данные хранятся в том виде, в котором получены или отправлены. Переключатель над полем: "Исходный текст" (по умолчанию) показывает данные как есть, "Форматированный" - JSON с переносами строк и отступами. Выбор запоминается.

Операции расширения:

| Операция | Когда пишется |
|---|---|
| `Конвейер` | Ошибка выполнения запроса или отказ процедуры подготовки ("Запрос ... не выполнен") |
| `RabbitMQ.Получение` | Получено сообщение из очереди или ошибка чтения очереди |
| `RabbitMQ.Отправка` | Сообщение опубликовано, не доставлено или отправлять было нечего |

Процедуры обработки пишут в журнал свои операции, например `Заказы.Прием`: так записи прикладной логики легко отобрать.

Как разобраться с запуском:

1. Отберите записи по настройке синхронизации и отсортируйте по периоду.
2. Найдите запуск с ошибкой и отберите записи по его идентификатору запуска.
3. Читайте записи по номеру: они показывают ход обмена шаг за шагом.

**Хранение.** Журнал не очищается автоматически. Для очистки есть функция `МС_ЖурналОбменаСервер.ОчиститьЖурнал(ДатаОбрезки)`: она удаляет записи старше указанной даты и возвращает их количество. Ее можно вызывать из своего регламентного задания или обработки.

## Права доступа

| Роль | Что дает |
|---|---|
| Основная роль (МС) | Полный доступ: настройки подключений, запросы, настройки синхронизации, журнал обмена, запуск обмена, Настройки API |
| Настройки интеграции базовые права (МС) | Просмотр настроек синхронизации и подключений. Запросы - только отмеченные для пользователя на закладке "Доступность" запроса, и только их значения параметров и соответствия |

Вторая роль нужна для пользователей, которые ведут прикладные настройки обмена (соответствия, параметры), но не должны менять подключения и код.
