# Менеджер синхронизаций

Расширение конфигурации 1С:Предприятие для обмена данными с внешними системами. Подключения, шаги обмена и расписание настраиваются в справочниках, а прикладная логика (что делать с полученными данными) пишется в обычных процедурах общих модулей. Результат каждого обмена виден в журнале.

## Возможности

- **Обмен по расписанию и вручную** с HTTP API, FTP-серверами, каталогами файлов, очередями RabbitMQ и источниками, к которым подключается код на встроенном языке (например, базы данных через ADO).
- **Загрузка и выгрузка в одном обмене.** Шаги выполняются по порядку и передают данные друг другу: принять сообщения, обработать, отправить ответы.
- **Настройки без доработки кода.** Параметры и таблицы соответствий (код во внешней системе - значение в базе) ведет аналитик, не трогая процедуры обработки.
- **Журнал обмена.** Полученные и отправленные сообщения, предупреждения и ошибки по каждому запуску, с исходным текстом сообщений.
- **HTTP API без программирования.** Публикация данных базы через HTTP-сервис: метод настраивается конструктором или текстом запроса. Конструктор выводит ссылки представлением, идентификатором, кодом или реквизитом, а отборы с фиксированным значением ограничивают данные так, что клиент API не может их обойти.
- **Команды на формах объектов.** Шаг обмена запускается из списка или формы документа, в том числе для выделенных строк.
- **Настройки доступа.** Пользователю можно открыть только параметры и соответствия отдельных запросов.

## Как это работает

**Настройка синхронизации** (`МС_НастройкиСинхронизации`) - один обмен. В ней указано соединение с источником, список шагов (табличная часть `НастройкиЗагрузки`) и расписание. По расписанию обмен запускает регламентное задание, вручную - кнопка "Выполнить обмен".

**Настройка подключения** (`МС_НастройкиПодключений`) хранит адрес, учетные данные и параметры соединения: HTTP, FTP или произвольное подключение кодом. Пароли лежат в безопасном хранилище БСП. Одна настройка подключения используется в нескольких обменах.

**Запрос к внешнему источнику** (`МС_ЗапросыКВнешнимИсточникам`) - один шаг обмена: загрузка или выгрузка, транспорт (файлы из каталога, файлы с FTP, RabbitMQ, код на встроенном языке), параметры и соответствия. К запросу подключаются две процедуры: подготовка данных до обращения к источнику и обработка результата после.

Как проходит один запуск:

1. Строки настроек загрузки выполняются сверху вниз, неактивные пропускаются.
2. Для каждой строки вызывается процедура подготовки. Она может подготовить данные для отправки или отменить шаг.
3. Запрос обращается к источнику: читает файлы или сообщения либо отправляет подготовленные данные.
4. Процедура обработки получает результат: создает объекты базы, готовит ответы для следующих шагов.
5. Все события пишутся в журнал обмена (`МС_ЖурналОбмена`) с общим идентификатором запуска.

**Настройка API** (`МС_НастройкиAPI`) работает в обратную сторону: внешняя система сама запрашивает данные базы по адресу `<публикация>/hs/sm/<версия>/<метод>`, а настройка описывает, какие данные отдать и какие параметры принять.

## Требования

- 1С:Предприятие 8.3.14 или новее.
- Конфигурация с Библиотекой стандартных подсистем (БСП).
- Для добавления команд запуска на формы нужны общие модули `МодификацияКонфигурацииПереопределяемый` и `МодификацияКонфигурацииКлиентПереопределяемый`: расширение их заимствует.
- Разрабатывается и проверяется на ERP 2.5.

## Установка

1. Скачать файл расширения `.cfe` из [раздела релизов](https://github.com/kropachev/1c-sync-manager/releases).
2. В режиме 1С:Предприятие открыть "Администрирование" - "Печатные формы, отчеты и обработки" - "Расширения" и добавить расширение из файла.
3. В свойствах расширения снять флажок "Безопасный режим": расширению нужны HTTP- и FTP-соединения, работа с файлами и привилегированный режим (подробнее - в разделе [Безопасность](#безопасность)).
4. Перезапустить сеанс.
5. Назначить пользователям роли: "Основная роль (МС)" - администраторам обмена, "Настройки интеграции базовые права (МС)" - пользователям, которые ведут параметры и соответствия отдельных запросов.
6. Для HTTP API опубликовать базу на веб-сервере с HTTP-сервисом `МС_HTTPAPI`.

Сборка из исходников: в конфигураторе создать расширение и загрузить его из файлов этого репозитория (Конфигурация - Расширения конфигурации - Действия - Конфигурация - Загрузить конфигурацию из файлов).

## Пример: загрузка курсов валют

Простой пример, на котором видна логика обмена: получить курсы валют ЦБ РФ из открытого API [cbr-xml-daily.ru](https://www.cbr-xml-daily.ru), записать курсы выбранных валют в регистр сведений "Курсы валют" конфигурации ERP и отразить результат в журнале обмена. Для загрузки курсов в рабочей базе есть штатные средства БСП: пример приведен только для демонстрации, запускайте его в тестовой базе.

### Подключение

"Менеджер синхронизаций (МС)" - "Настройки подключений (МС)" - "Создать":

| Поле | Значение |
|---|---|
| Наименование | `cbr-xml-daily.ru` |
| Вид подключения | HTTP |
| Сервер | `https://www.cbr-xml-daily.ru` |

Записать и нажать "Проверить соединение": должно появиться "Соединение установлено".

### Запрос

"Запросы к внешним источникам (МС)" - "Создать":

| Поле | Значение |
|---|---|
| Наименование | `Загрузить курсы валют ЦБ` |
| Тип обмена | Загрузка |
| Способ получения данных | Произвольный результат |
| Использовать код запроса | Включено |
| Код запроса | Код выбранного варианта, см. ниже |

На закладке "Значения параметров" добавить строку: имя параметра `Валюты`, значение `USD, EUR, CNY` с типом "Строка" (тип значения выбирается при вводе в ячейку). Записать запрос.

#### Вариант 1. Весь код в настройке запроса

Код получает JSON с курсами, берет из параметра `Валюты` список нужных валют, записывает курс каждой в регистр сведений "Курсы валют" и пишет запись в журнал обмена:

```bsl
Ответ = МС_ПодключенияСервер.ВыполнитьHTTPЗапрос(СтруктураСоединения, "GET", "/daily_json.js");
Если Ответ.КодСостояния <> 200 Тогда
	ВызватьИсключение "Сервис курсов вернул код " + Ответ.КодСостояния + ". " + Ответ.СтрокаОшибок;
КонецЕсли;
Курсы = МС_ПодключенияСервер.ПрочитатьОтветJSON(Ответ);
ДатаКурса = Дата(СтрЗаменить(Лев(Курсы.Date, 10), "-", ""));

Валюты = МС_СинхронизацияСервер.ЗначениеПараметра(СтруктураПараметров.ЗначенияПараметров, "Валюты");
Для Каждого КодВалюты Из СтрРазделить(Валюты, ", ", Ложь) Цикл
	ДанныеКурса = Неопределено;
	Валюта = Справочники.Валюты.НайтиПоНаименованию(КодВалюты, Истина);
	Если Не Курсы.Valute.Свойство(КодВалюты, ДанныеКурса) Или Валюта.Пустая() Тогда
		МС_ЖурналОбменаСервер.ДобавитьЗапись(СтруктураПараметров, Перечисления.МС_УровниЖурналаОбмена.Предупреждение,
			"Курс " + КодВалюты + " не записан: валюты нет в ответе сервиса или в справочнике ""Валюты""", "Пример.Курсы");
		Продолжить;
	КонецЕсли;

	Запись = РегистрыСведений.КурсыВалют.СоздатьМенеджерЗаписи();
	Запись.Период = ДатаКурса;
	Запись.Валюта = Валюта;
	Запись.Курс = ДанныеКурса.Value;
	Запись.Кратность = ДанныеКурса.Nominal;
	Запись.Записать();

	МС_ЖурналОбменаСервер.ДобавитьЗапись(СтруктураПараметров, Перечисления.МС_УровниЖурналаОбмена.Информация,
		СтрШаблон("Записан курс %1 на %2: %3 руб. за %4", КодВалюты, Формат(ДатаКурса, "ДЛФ=D"),
			ДанныеКурса.Value, ДанныеКурса.Nominal), "Пример.Курсы");
КонецЦикла;
```

Код выполняется внутри расширения, поэтому объекты расширения и конфигурации (справочник "Валюты", регистр "Курсы валют") вызываются напрямую. Такой вариант удобен для проверки и разовых задач.

#### Вариант 2. Обработка в общем модуле

Код запроса только получает и разбирает ответ API: значение переменной `РезультатЗапроса` передается в процедуру обработки.

```bsl
Ответ = МС_ПодключенияСервер.ВыполнитьHTTPЗапрос(СтруктураСоединения, "GET", "/daily_json.js");
Если Ответ.КодСостояния <> 200 Тогда
	ВызватьИсключение "Сервис курсов вернул код " + Ответ.КодСостояния + ". " + Ответ.СтрокаОшибок;
КонецЕсли;
РезультатЗапроса = МС_ПодключенияСервер.ПрочитатьОтветJSON(Ответ);
```

В поле "Процедура обработки данных после обмена" запроса указать `ИмяОбщегоМодуля.ЗаписатьКурсы`. В конфигурации или в своем расширении создать общий модуль с флажком "Сервер" и процедурой, которая берет из параметра `Валюты` список нужных валют, записывает курс каждой в регистр сведений "Курсы валют" и пишет запись в журнал обмена:

```bsl
Процедура ЗаписатьКурсы(НастройкиСинхронизации, СтруктураПараметров, РезультатЗапроса, РезультатЗагрузки) Экспорт

	Синхронизация = ОбщегоНазначения.ОбщийМодуль("МС_СинхронизацияСервер");
	Журнал = ОбщегоНазначения.ОбщийМодуль("МС_ЖурналОбменаСервер");
	Информация = ПредопределенноеЗначение("Перечисление.МС_УровниЖурналаОбмена.Информация");
	Предупреждение = ПредопределенноеЗначение("Перечисление.МС_УровниЖурналаОбмена.Предупреждение");

	ДатаКурса = Дата(СтрЗаменить(Лев(РезультатЗапроса.Date, 10), "-", ""));
	Валюты = Синхронизация.ЗначениеПараметра(СтруктураПараметров.ЗначенияПараметров, "Валюты");
	Для Каждого КодВалюты Из СтрРазделить(Валюты, ", ", Ложь) Цикл
		ДанныеКурса = Неопределено;
		Валюта = Справочники.Валюты.НайтиПоНаименованию(КодВалюты, Истина);
		Если Не РезультатЗапроса.Valute.Свойство(КодВалюты, ДанныеКурса) Или Валюта.Пустая() Тогда
			Журнал.ДобавитьЗапись(СтруктураПараметров, Предупреждение,
				"Курс " + КодВалюты + " не записан: валюты нет в ответе сервиса или в справочнике ""Валюты""",
				"Пример.Курсы");
			Продолжить;
		КонецЕсли;

		Запись = РегистрыСведений.КурсыВалют.СоздатьМенеджерЗаписи();
		Запись.Период = ДатаКурса;
		Запись.Валюта = Валюта;
		Запись.Курс = ДанныеКурса.Value;
		Запись.Кратность = ДанныеКурса.Nominal;
		Запись.Записать();

		Журнал.ДобавитьЗапись(СтруктураПараметров, Информация,
			СтрШаблон("Записан курс %1 на %2: %3 руб. за %4", КодВалюты, Формат(ДатаКурса, "ДЛФ=D"),
				ДанныеКурса.Value, ДанныеКурса.Nominal), "Пример.Курсы");
	КонецЦикла;

КонецПроцедуры
```

Модуль лежит вне расширения, поэтому объекты расширения вызываются по имени (`ОбщегоНазначения.ОбщийМодуль`, `ПредопределенноеЗначение`): прямые ссылки на них конфигуратор не распознает. Объекты конфигурации (справочник "Валюты", регистр "Курсы валют") вызываются напрямую.

### Настройка синхронизации и проверка

1. "Настройки синхронизации (МС)" - "Создать": наименование `Загрузка курсов валют`, в поле "Соединение" - подключение `cbr-xml-daily.ru`, в таблицу "Настройки загрузки" - строка с запросом `Загрузить курсы валют ЦБ` и флажком "Активно". Записать.
2. Нажать "Выполнить обмен".
3. Открыть регистр сведений "Курсы валют": на дату курса ЦБ появились записи по USD, EUR и CNY. Повторный запуск в тот же день перезаписывает эти же записи, дублей не будет.
4. Открыть "Журнал обмена (МС)": три записи с операцией `Пример.Курсы`, например "Записан курс USD на 08.10.2026: 85,7116 руб. за 1". Если валюты нет в справочнике "Валюты", будет предупреждение. Если сервис недоступен, будет ошибка с операцией `Конвейер` и текстом "Сервис курсов вернул код ...".

Обмен, запущенный кнопкой, выполняется с правами текущего пользователя: ему нужно право записи в регистр "Курсы валют". По расписанию обмен идет в привилегированном режиме.

Любой обмен устроен по этой схеме: меняются источник, способ получения данных и процедура обработки. Другие источники, расписание и параметры - в разделе [Инструкции](#инструкции).

## Пример: выдача курсов через HTTP API

Обратная задача: внешняя система сама запрашивает курсы валют из базы. Данные берутся из регистра сведений "Курсы валют" конфигурации ERP, код писать не нужно. Для примера база должна быть опубликована на веб-сервере.

### Настройка API

"Менеджер синхронизаций (МС)" - "Настройки API (МС)" - "Создать".

Шапка:

| Поле | Значение |
|---|---|
| Наименование | `Курсы валют на дату` |
| HTTP-метод | GET |
| Версия | `v1` |
| Параметр URL | `rates` |

Закладка "Получение данных":

| Поле | Значение |
|---|---|
| Способ получения данных | Конструктор |
| Тип источника | Регистр сведений |
| Объект метаданных | Курсы валют |
| Виртуальная таблица | Срез последних |
| Параметр периода | `date` |

Срез последних дает последний курс каждой валюты на дату из параметра `date`. Если дата не передана, выдаются текущие курсы.

Поля ответа (лишние отметки снять):

| Поле | Формат | Реквизит | Имя в ответе |
|---|---|---|---|
| Валюта | Реквизит | Наименование | `currency` |
| Валюта | Реквизит | Наименование полное | `name` |
| Курс | | | `rate` |
| Кратность | | | `nominal` |
| Период | | | `rateDate` |

Поле "Валюта" добавлено двумя строками: в справочнике "Валюты" буквенный код (USD) хранится в наименовании, а название - в реквизите "Наименование полное". Реквизит выбирается кнопкой выбора в колонке "Реквизит".

Отборы: одна строка - поле "Валюта", сравнение `=`, параметр запроса `currency`.

Чтобы метод отдавал только определенную валюту, нужно добавить отбор "Валюта = RUB" с фиксированным значением. Фиксированное значение важнее параметров: клиент API не получит другие валюты, даже если передаст `currency=USD`.

Закладка "Параметры HTTP и сериализация":

- в таблице "Параметры запроса" уже есть `date` (тип `ДАТА`, из параметра периода) и `currency` (из отбора). Оба оставить необязательными: без `date` выдаются текущие курсы, без `currency` - курсы всех валют. Для `currency` выбрать сопоставление строки "Наименование": так строка `USD` ищется по наименованию валюты;
- формат ответа - JSON, формат дат - ISO 8601.

Записать элемент.

### Проверка

1. Закладка "Проверка и пример ответа": в таблице "Тестовые значения" указать `currency` = `USD`, записать и нажать "Тест". Под таблицей появится ответ.
2. В шапке включить "Активно" и записать: новые настройки создаются выключенными.
3. Открыть в браузере адрес из поля "Адрес API" и ввести логин и пароль пользователя информационной базы, например:

   ```
   https://erp.example.ru/erp/hs/sm/v1/rates?currency=USD&date=2026-01-15
   ```

Ответ:

```json
{
  "apiVersion": "v1",
  "data": [
    {
      "currency": "USD",
      "name": "Доллар США",
      "reate": 78.5711,
      "nominal": 1,
      "rateDate": "2026-01-15T00:00:00"
    }
  ]
}
```

Вызов выполняется с правами пользователя, под которым внешняя система подключается к публикации: ему нужны права на чтение регистра "Курсы валют" и справочника "Валюты". Подробнее о параметрах, формате ответа и ошибках - в инструкции [Настройки API](src/cfe/МенеджерСинхронизаций/docs/nastrojki_api.md).

## Безопасность

Расширение работает с внешними ресурсами и выполняет код из настроек, поэтому требует доверия:

- **Безопасный режим выключен.** В безопасном режиме платформа запрещает HTTP- и FTP-соединения, работу с файлами и привилегированный режим, без которых обмен не работает.
- **Код из настроек выполняется на сервере.** Код произвольного подключения, код запроса и имена процедур обработки выполняются через `Выполнить`. Кто может изменять настройки, тот может выполнить любой код в базе.
- **Обмен по расписанию идет в привилегированном режиме.** Процедуры обработки при этом не ограничены правами пользователей.

## Ограничения и статус

Расширение в разработке. Текущие ограничения:

- проверяется только на ERP 2.5, на других конфигурациях с БСП работа не проверялась;
- RabbitMQ подключается через Management HTTP API: подходит для небольших потоков, сообщения забираются опросом по расписанию, а не подпиской;
- журнал обмена не очищается автоматически: для очистки есть функция `МС_ЖурналОбменаСервер.ОчиститьЖурнал`.
